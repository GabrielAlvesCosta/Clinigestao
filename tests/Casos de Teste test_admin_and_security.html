CT-01 — Redirecionamento de Administrador

ObjetivoGarantir que um usuário com privilégio de administrador seja redirecionado para a rota correta de gestão.

def test_01_adm_route_redirects_to_admin_panel_for_admin_user(client):

        sess['usuario'] = {
            'id': 1,
            'nome': 'Admin',
            'email': 'admin@test.com',
            'cargo': 'Gerente',
            'crm_coren': '12345',
            'admin': 'sim',
            'assinatura': ''

CT-03 — Unicidade e Criptografia do CRM/COREN

Técnicapytest.raises(ValueError) e query SQLite

def test_03_crm_coren_unique_and_encrypted():
    with app.app_context():
        Usuario('Dr. A', 'a@t.com', 'Médico', 'CRM-123', 's').salvar()
        with pytest.raises(ValueError):
            Usuario('Dr. B', 'b@t.com', 'Médico', 'CRM-123', 's').salvar()

        assert row['crm_coren'].startswith('gAAAAA')

Resumo das técnicas utilizadas

Técnica Quando usar
client.session_transaction() Para modificar variáveis simulando diferentes perfis logados (Ex: Admin vs Comum).
pytest.raises(ValueError) Garantir que a aplicação recusa duplicatas e protege a integridade do banco.
@patch e MagicMock() Isolar testes unitários, interceptar conexões a banco de dados e simular dados falsos de retorno sem IO.
sqlite3.connect() / get_db() Validar o estado final dos dados na persistência efetuando queries diretas após requisições HTTP (Integração).

Como executar os testes

A partir da raiz do projeto (sistema-gestao-clinica/):

# Rodar todos os testes do projeto (ignorando warnings de depreciação)
pytest -W ignore

# Rodar exibindo detalhes de cada caso aprovado/falho
pytest -v

# Rodar os testes focados apenas nas lógicas do Usuario
pytest tests/test_usuario.py -v
